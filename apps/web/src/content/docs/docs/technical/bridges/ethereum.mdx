# HASHI Bridge

[HASHI](/glossary/hashi) is SORA's decentralized and trustless cross-chain bridge that enables secure asset transfers between Ethereum and the SORA network. Unlike centralized bridges, HASHI uses cryptographic proofs to validate transactions across chains without relying on trusted intermediaries.

## Key Features

## How HASHI Works

### Architecture Overview

```
┌─────────────────┐                    ┌─────────────────┐
│    Ethereum     │                    │      SORA       │
│    Network      │                    │     Network     │
│                 │                    │                 │
│  ┌───────────┐  │    Validators     │  ┌───────────┐  │
│  │  Bridge   │◄─┼─── Sign & Relay ──┼─►│  Bridge   │  │
│  │ Contract  │  │    Proofs         │  │  Pallet   │  │
│  └───────────┘  │                    │  └───────────┘  │
│        │        │                    │        │        │
│  ┌─────▼─────┐  │                    │  ┌─────▼─────┐  │
│  │   ERC-20  │  │                    │  │   Asset   │  │
│  │   Tokens  │  │                    │  │  (Wrapped)│  │
│  └───────────┘  │                    │  └───────────┘  │
└─────────────────┘                    └─────────────────┘
```

### Bridge Flow: Ethereum → SORA

<Tabs>
  <TabItem label="Step 1: Lock">
    User deposits tokens into the Ethereum bridge contract:
    
    ```solidity
    // Approve tokens
    token.approve(bridgeAddress, amount);
    
    // Deposit to bridge
    bridge.deposit(tokenAddress, amount, soraRecipient);
    ```
  </TabItem>
  <TabItem label="Step 2: Relay">
    SORA validators observe the Ethereum transaction:
    
    1. Wait for sufficient confirmations
    2. Generate cryptographic proof
    3. Submit proof to SORA network
    4. Reach consensus on validity
  </TabItem>
  <TabItem label="Step 3: Mint">
    SORA network mints wrapped tokens:
    
    ```
    // On SORA
    Mint wrapped_DAI to user_account
    Amount: deposited_amount - bridge_fee
    ```
  </TabItem>
</Tabs>

### Bridge Flow: SORA → Ethereum

<Tabs>
  <TabItem label="Step 1: Burn">
    User burns wrapped tokens on SORA:
    
    ```
    // Submit withdrawal request
    bridge.withdraw(
        asset_id: "DAI",
        amount: 1000,
        eth_recipient: "0x..."
    )
    ```
  </TabItem>
  <TabItem label="Step 2: Aggregate">
    Validators aggregate signatures:
    
    1. Validators sign withdrawal request
    2. Threshold signatures collected
    3. Proof constructed
  </TabItem>
  <TabItem label="Step 3: Release">
    Tokens released on Ethereum:
    
    ```solidity
    // User or relayer submits proof
    bridge.withdraw(
        tokenAddress,
        amount,
        recipient,
        validatorSignatures
    );
    ```
  </TabItem>
</Tabs>

## Security Model

### Validator Security

HASHI relies on SORA's validator set:

| Layer | Mechanism |
|-------|-----------|
| Economic | Validators stake [VAL](/glossary/val) as collateral |
| Consensus | BFT requires 2/3+ honest validators |
| Slashing | Malicious behavior penalized |
| Rotation | Validator set changes over time |

### Cryptographic Proofs

Bridge transfers are secured by:

- **Merkle proofs** — Verify transaction inclusion
- **Threshold signatures** — Multiple validators must sign
- **Finality guarantees** — Wait for sufficient confirmations

### No Single Point of Failure

```
Traditional Bridge:          HASHI:
                            
    ┌─────────┐             ┌───┐ ┌───┐ ┌───┐
    │Multisig │             │ V │ │ V │ │ V │
    │  3/5    │             └─┬─┘ └─┬─┘ └─┬─┘
    └────┬────┘               │     │     │
         │                  ┌─▼─────▼─────▼─┐
    Single Point            │   Consensus   │
    of Failure              │   Required    │
                            └───────────────┘
```

## Fees

### Fee Structure

| Component | Fee | Recipient |
|-----------|-----|-----------|
| Bridge Fee | ~0.1% | SORA Treasury |
| Ethereum Gas | Variable | Ethereum Miners |
| SORA Fee | Minimal | Validators |

### Gas Optimization

HASHI batches operations to reduce costs:

- Multiple withdrawals aggregated
- Signature aggregation reduces calldata
- Off-peak submission for lower gas

## Using HASHI

### Via Polkaswap UI

The easiest way to use HASHI:

1. Go to [polkaswap.io](https://polkaswap.io)
2. Select "Bridge" tab
3. Connect Ethereum wallet (MetaMask)
4. Connect SORA wallet (Fearless/Polkadot.js)
5. Select token and amount
6. Confirm transactions

### Via Code

For programmatic access:

```typescript
import { ethers } from 'ethers';

// Connect to Ethereum
const provider = new ethers.providers.Web3Provider(window.ethereum);
const signer = provider.getSigner();

// Bridge contract
const bridge = new ethers.Contract(BRIDGE_ADDRESS, BRIDGE_ABI, signer);

// Approve tokens
const token = new ethers.Contract(TOKEN_ADDRESS, ERC20_ABI, signer);
await token.approve(BRIDGE_ADDRESS, amount);

// Deposit to bridge
const tx = await bridge.deposit(
    TOKEN_ADDRESS,
    amount,
    soraAccountBytes32  // SORA recipient
);

await tx.wait();
```

## Troubleshooting

### Common Issues

<Tabs>
  <TabItem label="Slow Transfer">
    **Causes:**
    - Ethereum congestion
    - Insufficient confirmations
    - Validator sync issues
    
    **Solution:**
    - Wait for more confirmations
    - Check bridge status page
    - Contact support if > 1 hour
  </TabItem>
  <TabItem label="Failed Transaction">
    **Causes:**
    - Insufficient gas
    - Token not approved
    - Bridge paused
    
    **Solution:**
    - Increase gas limit
    - Re-approve token
    - Check announcements
  </TabItem>
  <TabItem label="Wrong Amount">
    **Causes:**
    - Fee deducted
    - Decimal mismatch
    
    **Solution:**
    - Verify fee structure
    - Check token decimals
  </TabItem>
</Tabs>

<Aside type="caution">
Never send tokens directly to the bridge contract address. Always use the official UI or SDK methods.
</Aside>
