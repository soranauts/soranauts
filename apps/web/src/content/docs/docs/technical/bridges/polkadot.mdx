# Polkadot Bridge (XCM)

SORA v2 operates as a [parachain](/glossary/parachain) in the [Polkadot](/glossary/polkadot) ecosystem, enabling native cross-chain communication through [XCM (Cross-Consensus Messaging)](/glossary/xcm). This integration provides shared security, interoperability with other parachains, and access to the broader Polkadot DeFi ecosystem.

    ┌───────▼───────┐ ┌─────▼─────┐ ┌───────▼───────┐

    │  Parachain    │ │ Parachain │ │   Parachain   │
    │               │ │           │ │               │
    │ ┌───────────┐ │ │           │ │               │
    │ │ Polkaswap │ │ │           │ │               │
    │ │   DEX     │ │ │           │ │               │
    │ └───────────┘ │ │           │ │               │
    └───────────────┘ └───────────┘ └───────────────┘

### Benefits of Parachain Status

| Benefit | Description |
|---------|-------------|
| **Security** | Validators shared with relay chain |
| **Finality** | Blocks finalized by relay chain |
| **Interop** | Native XCM with all parachains |
| **Upgrades** | Forkless runtime upgrades |

## XCM Overview

### What is XCM?

XCM is a messaging format that allows different consensus systems to communicate:

- **Cross-Consensus** — Works across different blockchains
- **Messaging** — Structured instruction format
- **Versioned** — Backward compatible upgrades

### XCM Instruction Types

<Tabs>
  <TabItem label="Asset Transfer">
    Move assets between chains:
    
    ```rust
    Xcm(vec![
        // Withdraw from origin
        WithdrawAsset(assets.clone()),
        
        // Buy execution on destination
        BuyExecution { 
            fees: fee_asset,
            weight_limit: Unlimited 
        },
        
        // Deposit to recipient
        DepositAsset {
            assets: Wild(All),
            beneficiary: destination_account,
        },
    ])
    ```
  </TabItem>
  <TabItem label="Remote Call">
    Execute logic on another chain:
    
    ```rust
    Xcm(vec![
        WithdrawAsset(fees.clone()),
        BuyExecution { fees, weight_limit: Unlimited },
        
        // Execute call on remote chain
        Transact {
            origin_kind: OriginKind::SovereignAccount,
            require_weight_at_most: Weight::MAX,
            call: encoded_call.into(),
        },
    ])
    ```
  </TabItem>
  <TabItem label="Query Response">
    Request information from another chain:
    
    ```rust
    Xcm(vec![
        // Query account balance on remote chain
        QueryHolding {
            query_id: 42,
            dest: destination,
            assets: Wild(All),
            max_response_weight: Weight::MAX,
        },
    ])
    ```
  </TabItem>
</Tabs>

## Asset Transfers

### Transferring to SORA

From another parachain to SORA:

```rust
// On source parachain
let xcm_message = Xcm(vec![
    WithdrawAsset(MultiAssets::from(vec![
        (GeneralIndex(asset_id), amount).into()
    ])),
    InitiateReserveWithdraw {
        assets: Wild(All),
        reserve: SORA_PARACHAIN_LOCATION,
        xcm: Xcm(vec![
            BuyExecution { 
                fees: (GeneralIndex(XOR_ID), fee).into(),
                weight_limit: Unlimited,
            },
            DepositAsset {
                assets: Wild(All),
                beneficiary: sora_account,
            },
        ]),
    },
]);

pallet_xcm::send(origin, dest, xcm_message)?;
```

### Transferring from SORA

From SORA to another parachain:

```rust
// On SORA
let xcm_message = Xcm(vec![
    WithdrawAsset(MultiAssets::from(vec![
        (GeneralIndex(ASSET_ID), amount).into()
    ])),
    InitiateTeleport {
        assets: Wild(All),
        dest: DESTINATION_PARACHAIN,
        xcm: Xcm(vec![
            BuyExecution { fees, weight_limit: Unlimited },
            DepositAsset {
                assets: Wild(All),
                beneficiary: recipient,
            },
        ]),
    },
]);
```

## Technical Details

### MultiLocation

Assets and accounts are identified by MultiLocation:

```rust
// SORA on Polkadot
MultiLocation {
    parents: 0,
    interior: X1(Parachain(SORA_PARA_ID)),
}

// XOR on SORA
MultiLocation {
    parents: 0,
    interior: X2(
        Parachain(SORA_PARA_ID),
        GeneralKey(XOR_ASSET_ID),
    ),
}

// Account on SORA
MultiLocation {
    parents: 0,
    interior: X2(
        Parachain(SORA_PARA_ID),
        AccountId32 { network: None, id: account_bytes },
    ),
}
```

### Weight and Fees

XCM operations consume weight:

| Operation | Approximate Weight |
|-----------|-------------------|
| WithdrawAsset | 1,000,000 |
| DepositAsset | 1,000,000 |
| BuyExecution | 500,000 |
| Transact | Variable |

<Aside type="tip">
Always include sufficient fees in `BuyExecution` to ensure your message is processed.
</Aside>

## Polkaswap XCM Integration

### Trading Cross-Chain Assets

[Polkaswap](/glossary/polkaswap) can trade assets from any connected parachain:

1. **Receive via XCM** — Assets bridged to SORA
2. **Wrap if needed** — Foreign assets wrapped
3. **Trade on DEX** — Swap for any listed pair
4. **Send via XCM** — Transfer results to destination

### Liquidity Aggregation

Polkaswap aggregates liquidity across:

- Native SORA pools
- XCM-bridged assets
- Ethereum-bridged assets (via HASHI)

## Development

### Testing XCM

Use local relay chain for testing:

```bash
# Start local Polkadot relay
zombienet spawn config.toml

# Deploy SORA parachain
./target/release/sora-parachain \
    --collator \
    --chain sora-local
```

### Debugging

Common XCM issues:

| Error | Cause | Solution |
|-------|-------|----------|
| `TooExpensive` | Insufficient fees | Increase BuyExecution amount |
| `AssetNotFound` | Unregistered asset | Register asset first |
| `LocationNotFound` | Wrong destination | Check MultiLocation format |
| `Barrier` | Security filter | Verify allowed origins |
