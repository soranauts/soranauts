## Service Level Objectives

### Availability SLO

| Metric | Target | Measurement |
|--------|--------|-------------|
| **Uptime** | 99.9% | Rolling 30-day window |
| **Error Rate** | < 0.1% | 5xx responses / total requests |
| **DNS Resolution** | < 100ms p95 | Synthetic monitoring |

**Calculation:**
```
Availability = (Total Minutes - Downtime Minutes) / Total Minutes × 100

30-day budget at 99.9% = 43.2 minutes downtime allowed
```

### Error Budget Policy

#### Budget Calculation

```
Monthly Error Budget = 100% - SLO Target

At 99.9% availability:
- Monthly budget = 0.1% = 43.2 minutes
- Weekly budget = ~10.8 minutes
- Daily budget = ~1.44 minutes
```

#### Escalation Tiers

| Budget Consumed | Action |
|-----------------|--------|
| 0-50% | Normal operations |
| 50-75% | Increased monitoring, defer risky changes |
| 75-90% | Change freeze, incident review |
| 90-100% | Emergency response, rollback if needed |
| >100% | Mandatory postmortem, remediation plan |

#### Rollback Triggers

Automatic rollback consideration when:

1. **Availability breach** — Error rate > 1% for 15 minutes
2. **Performance breach** — LCP > 4s for 30 minutes
3. **Functionality breach** — Quick-View fails for 10+ users
4. **Data breach** — Glossary JSON returns 404/500

## Change Policy During Lock

### Allowed Without Approval

- Content updates (MDX edits)

### Requires Approval

- Any code changes
- Configuration changes
- Infrastructure changes

### Frozen Until Q1 2026

- Schema changes
